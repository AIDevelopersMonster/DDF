## 1. Цель и критерии окончания работы

Реализовать четырёхточечный FIR-фильтр скользящего среднего как синтезируемое цифровое устройство и проверить его сначала имитационно, затем на физической FPGA, используя независимый эталон на ПК.

Критерии функциональной приёмки:

1. Точный интерфейс RTL и последовательность принятых отсчётов определены до испытаний.
2. Положительный HDL-тест выполнен; заведомо повреждённый RTL отклонён тестом.
3. Gowin формирует конфигурацию для выбранного семейства FPGA.
4. JTAG обнаруживает плату; контрольная конфигурация работает физически.
5. Встроенный аппаратный BIST выдаёт ожидаемую индикацию.
6. Внешняя UART-проверка получает действительные ответы FPGA и сравнивает их с отдельной программной моделью.
7. Сохраняются версии, контрольные суммы, журналы удачных и неудачных опытов.

Эти критерии **выполнены для конечного функционального сценария** по имеющимся протоколам. Проверка временных ограничений после Place & Route, энергопотребления, надёжности и всех возможных последовательностей **не выполнена** в объёме, достаточном для соответствующих утверждений.

## 2. Функция и контракт вычислительного ядра

Файл: `rtl/moving_average4.v`, Verilog-2005.

Для очередного **принятого** беззнакового 12-битного отсчёта `x[n]`:

`y[n] = floor((x[n] + x[n-1] + x[n-2] + x[n-3]) / 4)`.

Недостающие отсчёты перед началом истории считаются нулевыми. Максимальная сумма `4 × 4095 = 16380`, для неё достаточно 14 бит. В схеме использованы три 12-битных регистра истории, 12-битный регистр результата и регистр `valid_out` (номинально 49 бит состояния).

- `valid_in=1`: ядро принимает новый отсчёт и регистрирует новое среднее.
- `valid_in=0`: история и `data_out` удерживаются, а `valid_out` деактивируется.
- `rst_n=0`: история, данные выхода и флаг достоверности сбрасываются.
- Интерфейс самого ядра **не имеет** `ready/backpressure`: внешний контроллер обязан соблюдать возможность приёма.

UART-обвязка реализует отдельный последовательный протокол «запрос → ответ» (*stop-and-wait*) и не изменяет этот контракт или исходный алгоритм.

Загрузка в SRAM через ранее проверенный интерфейс FT2CH:

```powershell

Push-Location (Split-Path $prog -Parent)
try {
    & $prog --device GW1NR-9C --operation_index 2 `
        --fsFile $fs --cable-index 1 2>&1 |
        Tee-Object -FilePath $log
    $progRc = $LASTEXITCODE
} finally { Pop-Location }
if ($progRc -ne 0) { throw "FPGA PROGRAMMING FAILED" }
```

После загрузки нажать и отпустить кнопку S1, закрыть все иные программы, владеющие COM10.

### Этап F. Внешний физический обмен и независимое сравнение


Программа отправляет команды по очереди, ждёт **шестибайтный ответ**, проверяет номер транзакции, заголовок, статус, XOR и 12-битный диапазон, затем сравнивает результат FPGA с собственной историей четырёх принятых отсчётов.

## 5. Протокол передачи данных

Ровно шесть байтов на запрос и ответ:

| Направление | Формат |
|---|---|
| ПК → FPGA | `A5 op seq hi lo xor` |
| FPGA → ПК | `5A status seq hi lo xor` |

`xor` — XOR пяти предыдущих байтов. `hi[3:0]` и `lo[7:0]` кодируют 12-битный отсчёт.

| Код | Команда / ответ |
|---|---|
| `01` | SAMPLE — принять новый отсчёт, возвратить новое среднее |
| `02` | RESET — очистить историю FIR |
| `03` | HOLD — не подавать новый отсчёт, вернуть удерживаемый результат |
| `00` | Статус OK |
| `E1` | Неверный код команды |
| `E2` | Ошибка контрольного XOR |
| `E3` | Значение вне 12-битного диапазона |

XOR не является криптографической проверкой и не обнаруживает все возможные многобитовые искажения. Этот обмен не является высокопроизводительным потоковым интерфейсом.

## 7. Инженерный анализ отказа v0.1

В версии v0.1 асинхронный сброс FIR зависел от комбинационного декодирования состояния конечного автомата:

```verilog
wire fir_rst_n = rst_n && (state != ST_SOFT_RESET);
```

В v0.2 управление программным сбросом вынесено в зарегистрированный сигнал `fir_soft_reset_hold`; сам модуль `moving_average4.v` не изменён.

**Наблюдение:** v0.1 прошла нулезадержечную HDL-симуляцию, но на плате выдала неверное значение уже на `seq=2`; v0.2 прошла моделирование и физическую серию из 294 транзакций.

**Обоснованная гипотеза:** промежуточный код FSM или комбинационный глитч мог кратковременно активировать асинхронный сброс и стереть историю FIR. **Не доказано:** фактическая форма/длительность такого импульса в кремнии. Для доказательства механизма требуется отдельное инструментирование (например, захват внутреннего сигнала или специально спроектированная проверка). Не подменять успешность исправления доказательством механизма отказа.

## 8. Границы результата и воспроизводимость

**Подтверждено:** математический контракт на выполненных тестах, базовая HDL-симуляция, отрицательные тесты, синтез ядра, рабочая JTAG-загрузка, аппаратный BIST, реальный обмен UART и успешное сравнение в серии v0.2.

**Не подтверждено отдельным доказательством:** итоговый timing closure по P&R, максимальная частота, энергопотребление, длительная надёжность, устойчивость к произвольному шуму UART, полная формальная эквивалентность RTL и аппаратуры, причинный механизм дефекта v0.1.

Не объединять показатели **49 регистров / 37 ALU / 1 LUT** ядра с итоговыми ресурсами версии UART: это разные уровни проекта. Версии исходных материалов v0.1 и журналы отказа хранить неизменными. Артефакты `build/` воспроизводятся Tcl-скриптами и могут не входить в Git; их SHA256 фиксируется в отчётах.
